# 需求分析文档

## 1. 项目背景

本项目面向校园图书馆场景，目标是构建一个轻量级、可学习、可扩展的图书借阅管理系统，用于模拟真实校园图书馆的业务闭环。系统聚焦于图书查询、借阅、归还、权限管理和日志审计等核心功能，采用 Spring Boot + Spring MVC + MyBatis + Spring Security 的基础技术栈，降低项目复杂度，突出学习主线。

## 2. 业务目标

1. 提供图书查询能力
   - 按关键词检索图书
   - 支持按书名、作者、分类查询
   - 展示图书状态和库存情况

2. 提供借阅与归还流程
   - 学生用户可借阅可用图书
   - 借阅成功后扣减库存并写入借阅记录
   - 用户归还图书后恢复库存并更新记录状态

3. 提供角色权限管理
   - 学生：查询图书、借阅、归还、查看自己的借阅记录
   - 管理员：新增/编辑图书、查看日志、维护图书信息

4. 提供操作审计能力
   - 记录借阅、归还、图书维护等关键操作
   - 管理员可查看操作日志，支持后续审计和学习演示

5. 适合学习与教学演示
   - 功能范围控制在“够用即可”
   - 不引入复杂分布式系统、微服务、缓存、消息队列等生产装饰

## 3. 业务角色定义

### 学生角色
- 图书查询
- 借阅图书
- 归还图书
- 查看自己的借阅记录

### 管理员角色
- 图书新增
- 图书信息更新
- 查看全部操作日志
- 审核和维护图书信息

## 4. 业务流程设计

### 4.1 图书查询流程
- 用户输入关键词
- 后端根据标题/作者/分类模糊查询
- 返回图书列表和库存信息

### 4.2 借阅流程
- 用户提交借阅请求
- 校验图书是否存在
- 校验库存是否大于 0
- 库存减 1
- 插入借阅记录
- 写入操作日志

### 4.3 归还流程
- 用户提交归还请求
- 校验借阅记录状态
- 归还时间写入记录
- 库存加 1
- 更新状态为 RETURNED
- 写入日志

### 4.4 管理员维护流程
- 管理员新增或更新图书信息
- 系统校验必要字段
- 数据写入数据库
- 日志记录操作行为

## 5. 全产业链思维设计（模拟协同）

虽然本项目是轻量级单体应用，但在架构思维上仍模拟“全产业链协同”场景，借助模块分层来体现数据流与协同闭环：

- 元数据管理：图书的信息维护，如书名、作者、分类、库存
- 用户与权限管理：学生/管理员角色划分
- 业务执行层：借阅、归还、查询
- 监督与审计层：日志记录、审计查询
- 安全认证层：Spring Security 对访问进行控制

这种设计使系统不仅是一个“功能堆砌”的 Demo，而是一个具备协同思维的业务闭环：

- 图书信息是上游资产
- 用户是借阅主体
- 借阅与归还是核心交易流程
- 日志与权限是控制和治理手段
- 管理层负责运维与审计

## 6. 非功能需求

### 6.1 轻量化原则
- 尽量使用单体应用结构，不引入复杂微服务和分布式组件
- 仅使用 H2 内存数据库以降低部署成本
- 聚焦业务逻辑和技术结合，而不是生产级设施

### 6.2 安全性要求
- 基础认证（HTTP Basic）
- 角色权限控制
- 仅允许管理员访问日志与图书维护接口

### 6.3 可维护性要求
- Controller、Service、Mapper 分层清晰
- 业务逻辑集中在 Service 层
- SQL 放在 Mapper XML 中，便于管理

## 7. 总结

本系统设计目标不是追求生产化复杂度，而是通过最小成本实现校园图书借阅管理流程，让学习者理解：

- Spring MVC 是如何承接 HTTP 接口请求
- MyBatis 是如何映射数据库操作
- Spring Security 是如何实现访问控制
- 事务和日志如何保证系统的可靠性与审计性

通过这个项目，学生能够从“做出一个能跑的系统”逐步走向“理解系统模块化与协同机制”。
